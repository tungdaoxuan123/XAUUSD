Gaps to Close Before Handing to the Coding Agent
1. config/settings.py is mentioned but not in the directory tree

Add it explicitly:

text
v3_trade/
├── config/
│   └── settings.py   # symbol, timeframes, risk%, session windows, thresholds
This file should be the single source of truth for all tunable parameters. The coding agent should never hardcode "XAUUSD", 0.01, or 60 anywhere in the logic files.

2. core/main_loop.py is missing from the directory tree

It appears in Phase 5's description but not in the tree. Add it:

text
├── core/
│   ├── voting.py
│   ├── risk.py
│   ├── main_loop.py    # orchestrator
│   └── logger.py       # structured per-signal and per-trade logging
logger.py should also be explicitly listed — without it, Phase 5 demo verification has no audit trail.

3. Economic calendar has no home

The architecture document specifies a pre-loaded weekly calendar for news blocking. Add:

text
├── utils/
│   ├── calendar.py     # news event loader and pre-trade gate check
│   └── session.py      # session window detection (Asian/London/NY)
4. Phase 3 unit tests need a tests/ directory

text
├── tests/
│   ├── test_strategies.py
│   ├── test_voting.py
│   └── test_risk.py
If you don't specify this, the coding agent will skip it or inline the tests, which breaks CI later.

5. Position monitor is missing from Phase 5

The architecture specifies trailing stop activation after TP1 hit and partial close logic. This is non-trivial and needs its own module:

text
├── core/
│   └── position_monitor.py  # trailing stop, TP1 partial close, breakeven logic
Currently Phase 5 only mentions order_send. The position monitor loop (which polls open positions every 30s) is a separate concern from the entry main loop and needs to be scoped explicitly.

One Risk to Flag
The plan defers the ML layer entirely, which is fine. But tell the coding agent to reserve the ML hook explicitly in core/voting.py as a passthrough stub:

python
# ml_filter is None until Part 6 is implemented
def ml_gate(signal, ml_filter=None):
    if ml_filter is None:
        return signal  # pass-through
    return ml_filter.evaluate(signal)
If this stub isn't placed now, retrofitting the ML layer into the voting engine later will require refactoring the core decision path — which is risky on a live bot.
