Issues & Gaps to Fix
🔴 Critical
1. EXHAUSTION_SHORT weight in BULL_TREND is 0.0
This means the exhaustion short can never fire in a bull trend — but blow-off tops happen during bull trends. This is the exact scenario you want to catch. Change this:

python
"EXHAUSTION_SHORT": {"BULL_TREND": 1.5, ...}  # was 0.0
Exhaustion shorts are most valid in BULL_TREND and VOLATILE — zero-weighting them there defeats the purpose.

2. ATR uses simple rolling mean, not Wilder's
Standard ATR uses Wilder's smoothing (EMA with alpha=1/period). The current rolling(p).mean() gives different values. For XAUUSD, the difference matters for SL/TP calculation. Fix:

python
df[f'ATR_{p}'] = true_range.ewm(alpha=1/p, adjust=False).mean()
🟡 Medium
3. confidence in execute_trade is a rough proxy

python
confidence = min(1.0, score / 4.0)
This caps at 1.0 when score=4.0 but a typical max score is 7–8 (6 strategies × weighted vote). The denominator should be closer to max_possible_score per regime. Consider passing final_score / self.voting_engine.max_score(regime) instead.

4. add_swing_points uses center=True rolling
This introduces look-ahead bias in live trading. In backtesting it's fine, but center=True means the swing point uses future bars. In live operation, shift(lookback) corrects for it, but verify this shift is consistent when len(df) is near the window boundary.

5. No session filter visible
The theory doc called for blocking trades during low-liquidity windows (00:00–02:00 UTC, 22:00–24:00 UTC). No session gate is visible in main_loop.py. Add a check before execute_trade.

6. ml_gate stub — correctly pass-through for now, but wire up when LightGBM model is ready.
